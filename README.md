A distributed hardware diagnostic engine that combines edge telemetry with static hardware benchmarking to accurately identify PC bottlenecks and prescribe physically and electrically compatible upgrades. 

Unlike generic bottleneck calculators that rely on crude percentage heuristics, this engine utilizes a **Two-Pass Diagnosis System** (Boolean Capacity Gates + Normalized Variance Mapping) tailored to specific workloads such as 1080p Gaming, 4K Video Editing, and Local AI/ML inference.

## Architecture & Core Features

* **Edge Telemetry Collection:** A lightweight Python client (`psutil`, `pynvml`) runs locally to gather real-time hardware utilization (CPU per-core pinning, VRAM thrashing, storage queue depth) without transmitting sensitive user data.
* **Two-Pass Diagnostic Engine:** 
  
  1. *Boolean Gatekeeper:* Validates absolute hardware floors (e.g., minimum VRAM for AI, required CPU instruction sets).
  
  2. *Variance Mapper:* Analyzes capacity versus throughput ratio mismatches based on workload demands using normalized vector distance.
* **Intelligent Upgrade Prescriptions:** Queries a localized SQLite hardware database (ported from `buildcores`) to suggest upgrades that strictly respect socket compatibility, case clearance, and PSU wattage limits.
* **Infrastructure as Code (IaC):** Fully reproducible cloud environment targeting the GCP Always-Free tier (`e2-micro`), provisioned via **Terraform** and configured via **Ansible**.
* **Zero-State Web Dashboard:** A fast, stateless Tailwind CSS frontend served via Nginx that visualizes diagnostic reports generated by the edge client via a unique UUID.

## Technology Stack

* **Edge Client:** Python (`psutil`, `requests`)
* **Backend API:** FastAPI, Uvicorn, Python 3.11
* **Database:** SQLite (WAL Mode)
* **Frontend:** HTML5, Tailwind CSS
* **Web Server:** Nginx Alpine
* **DevOps & Cloud:** Google Cloud Platform (GCP), Terraform, Ansible, Docker

## Local Development Environment

This stack can be executed entirely on a local development machine without requiring a cloud provider.

**1. Clone the repository and seed the database:**

```bash
git clone https://github.com/yourusername/bottleneck-remove.git
cd bottleneck-remove
python3 server/backend/db/seed_data.py
```

**2. Start the Server Stack (Docker):**

```bash
cd server
docker compose up --build -d
```

*The API initializes at `http://localhost:8000/api/` and the web UI at `http://localhost/`.*

**3. Run the Client Telemetry Probe:**

```bash
cd ../client
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# Execute the probe (generates the report and opens it in the default browser)
python3 collector.py
```

## Infrastructure & Cloud Deployment (GCP)

This project is configured to deploy to Google Cloud's **Always Free** tier (`us-central1`, `e2-micro`, 30GB Standard Disk). 

**1. Provision Infrastructure with Terraform:**

```bash
cd infra/terraform
# Define your GCP Project ID in terraform.tfvars prior to execution
terraform init
terraform apply
```

*Note the `server_public_ip` output generated upon completion.*

**2. Configure Host & Deploy with Ansible:**

```bash
cd ../ansible
# Append the generated IP to inventory.ini
ansible-playbook -i inventory.ini playbook.yml
```

Ansible will automatically authenticate, allocate a 2GB swap file to protect the 1GB RAM VM, install the Docker runtime, and initialize the `docker-compose.yml` stack.
